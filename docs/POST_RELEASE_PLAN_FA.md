# برنامهٔ پس از انتشار LAGSHIFT

این سند حافظهٔ تصمیم‌های محصول پس از انتشار نسخهٔ ۱.۰ است. ترتیب موارد، اولویت
پیشنهادی را نشان می‌دهد. هیچ قابلیت نباید فقط برای نمایش در رابط کاربری «موفق»
اعلام شود؛ نتیجه باید با تست واقعی و قابل‌توضیح تأیید شود.

## اولویت‌های قطعی

1. **دورهٔ تثبیت ۱.۰.x**
   - برای دو تا سه هفته فقط رفع باگ، کرش، ناسازگاری و مشکلات نصب/آپدیت انجام شود.
   - در این دوره قابلیت بزرگ تازه وارد نسخهٔ Stable نشود.

2. **Self-Repair و سلامت نصب**
   - در شروع برنامه سلامت فایل‌های اصلی، Qt و Python بررسی شود.
   - خرابی یا ناقص‌ماندن ارتقا با پیام ساده تشخیص داده شود.
   - گزینهٔ «ترمیم نصب» آخرین بستهٔ سالم و تأییدشده را نصب کند.
   - تنظیمات و داده‌های کاربر در تمام مراحل حفظ شوند.

3. **اثبات واقعی نتیجه و RouteDNA قبل/بعد**
   - وضعیت مقصدهای لازم پیش و پس از تغییر مسیر مقایسه شود.
   - موفقیت DNS، TCP، TLS، Login/API/CDN و زمان پاسخ جداگانه گزارش شود.
   - کاربر با زبان ساده ببیند چه چیزی بهتر شده و چرا مسیر انتخاب شده است.
   - صرف اجرای فرمان یا تغییر تنظیمات به‌معنای اتصال موفق نباشد.

4. **گزارش خطای یک‌کلیکی و اختیاری**
   - گزارش فقط با رضایت صریح کاربر ساخته یا ارسال شود.
   - نسخه، مرحلهٔ شکست و مشخصات عمومی و پاک‌سازی‌شدهٔ شبکه را شامل شود.
   - IP کامل، نام Wi-Fi، اطلاعات ورود، تاریخچهٔ مرور و محتوای برنامه جمع نشوند.
   - تا آماده‌شدن Backend، خروجی امن برای ثبت دستی در GitHub Issues فراهم شود.

5. **به‌روزرسانی مستقل پروفایل برنامه‌ها**
   - کاتالوگ پروفایل‌ها بدون انتشار EXE جدید قابل‌به‌روزرسانی باشد.
   - کاتالوگ با امضای دیجیتال تأیید و در صورت خرابی رد شود.
   - Cloudflare Worker رایگان می‌تواند نقطهٔ شروع باشد.
   - نسخهٔ داخلی و سالم پروفایل‌ها همیشه به‌عنوان fallback باقی بماند.

6. **راه‌اندازی اولیهٔ کوتاه و حرفه‌ای**
   - هدف اصلی: بازی یا برنامه.
   - نوع اینترنت: ثابت یا همراه.
   - دریافت رضایت آگاهانه برای RouteDNA و توضیح اطلاعات مورد استفاده.
   - اجرای تست سبک و ساخت اولین پیشنهاد واقعی.

7. **داشبورد سلامت**
   - اینترنت، DNS، WARP، آخرین مسیر موفق، سلامت نصب و وضعیت آپدیت را نشان دهد.
   - وضعیت‌ها شامل «در حال بررسی»، «تأییدشده»، «ناموفق» و «اطلاعات ناکافی» باشند.

8. **کنترل از System Tray**
   - اتصال، قطع، انتخاب پروفایل و مشاهدهٔ وضعیت از کنار ساعت ویندوز ممکن باشد.
   - رفتار بستن پنجره و ادامه یا قطع اتصال کاملاً شفاف و قابل‌تنظیم باشد.

9. **برنامهٔ تست عمومی محدود**
   - ابتدا با ۲۰ تا ۵۰ کاربر روی Windows 10 و 11 اجرا شود.
   - اینترنت‌های ایرانسل، همراه اول، مخابرات، شاتل و مبین‌نت پوشش داده شوند.
   - نتیجه‌ها براساس نسخه، اپراتور و نوع اتصال دسته‌بندی شوند، بدون ذخیرهٔ IP کامل.

10. **مرز دقیق ادعاهای محصول**
    - تغییر DNS فقط با عنوان «DNS فعال» نمایش داده شود.
    - WARP فقط پس از تأیید عبور واقعی ترافیک، فعال اعلام شود.
    - هیچ ادعای تضمینی برای کاهش پینگ، رفع محدودیت یا کارکرد روی همهٔ اپراتورها
      منتشر نشود.

## قابلیت شاخص پیشنهادی

مهم‌ترین تمایز محصول باید **RouteDNA قابل‌اثبات** باشد: مقایسهٔ قبل و بعد، نمایش
نتیجهٔ واقعی مقصدها، امتیاز اطمینان و توضیح سادهٔ علت انتخاب مسیر. این قابلیت باید
نشان دهد LAGSHIFT واقعاً چه تغییری ایجاد کرده است، نه اینکه فقط ظاهر اتصال را
نمایش دهد.

## ترتیب اجرای پیشنهادی

1. تثبیت ۱.۰.x و جمع‌آوری گزارش‌های واقعی
2. Self-Repair و سلامت نصب
3. RouteDNA قبل/بعد و Explain My Route
4. گزارش خطای اختیاری
5. کاتالوگ امضاشدهٔ پروفایل‌ها
6. راه‌اندازی اولیه، داشبورد سلامت و System Tray
7. تست عمومی محدود و انتشار نتایج سازگاری

هر مورد تنها زمانی «تکمیل‌شده» است که تست خودکار، تست واقعی روی ویندوز، مسیر
بازگشت امن، متن حریم خصوصی و نمایش درست RTL داشته باشد.
